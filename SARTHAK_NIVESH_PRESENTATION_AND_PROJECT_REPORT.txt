The Indian capital markets have witnessed an unprecedented retail investment 
boom over the last five years. Driven by digital brokerages, widespread smartphone

Qualified Institutional Buyers (QIBs), Foreign Institutional Investors (FIIs), and

"सार्थक निवेश" (Sarthak Nivesh — Meaningful Investment) is an end-to-end autonomous 
multi-agent financial intelligence platform. Designed specifically for the Indian 
market ecosystem, the platform does not rely on static web scrapers or generic 
chatbots. Instead, it deploys a dual-framework agentic system combining CrewAI and 
Anthropic Agent Development Kit (ADK) to synthesize multidimensional financial evidence.

1.3 Priority Module: The 6-Agent IPO Multi-Agent Framework
While the platform provides holistic wealth intelligence (including live stock 
analytics, mutual fund trackers, and macroeconomic monitors), its flagship core

IPO across price action, macro policies, sentiment, balance sheet debt, and subscription 
quality before delivering an authoritative INVEST, PARTIAL_INVEST, HOLD, or EXIT 
verdict paired with an automated multi-tier Dynamic Exit Strategy.

2. PROBLEM STATEMENT (Page 2-3)
================================================================================

2.1 What Problem is Being Addressed?
Retail investors in the Indian IPO market face three acute systemic barriers:
  1. The Information Asymmetry Trap: Institutional investors employ teams of quants 
     and analysts to dissect draft red herring prospectuses (DRHPs), capital structures, 
     and promoter pledges. Retail investors, conversely, rely primarily on unverified 
     social media rumors, unofficial Grey Market Premiums (GMP), and sensationalized 
     news headlines, resulting in severe listing-day losses during overhyped IPOs.
  2. The "Listing Gain" vs. "Long-Term Hold" Dilemma: Retail investors lack an 
     objective framework to decide what to do on listing day. When an IPO lists at a 
     premium, retail participants often hold through subsequent institutional distribution 
     declines; when an IPO lists at a discount, panic selling causes premature capital erosion.
  3. The Limitations of Single-Agent Chatbots: Generic AI models (e.g., standard ChatGPT) 
     suffer from hallucination, knowledge cutoffs, inability to access live NSE market 
     depth, and lack of mathematical rigor required for portfolio risk metrics.

2.2 Who Are the Intended Users?
  - Retail Stock & IPO Investors: Seeking objective, institutional-grade evaluation 
    before committing application capital.
  - Active Post-Listing Traders: Requiring quantified profit-booking ladders, support/resistance 
    levels, and trailing stop-losses.
  - Financial Advisors & Students: Needing transparent, observable reasoning paths 
    detailing why an investment decision was reached.

2.3 Why is a Multi-Agentic Solution Relevant?
Financial evaluation is inherently multidisciplinary. A single prompt or monolithic 
algorithm cannot simultaneously assess technical momentum, macro fiscal policies, NLP 
news sentiment, debt sustainability, and allocation mechanics without conflicting 
reasoning paths. By dividing the workload into specialized, autonomous domain agents:
  - Each agent focuses exclusively on its domain of expertise.
  - Agents challenge and validate each other's conclusions via reflection.
  - The Master Orchestrator synthesizes multiple independent vectors into an 
    unbiased, explainable recommendation.

4. METHODOLOGY (Page 7-16)
================================================================================

4.1 The 6-Agent Hierarchical Architecture
The core architecture operates on a hierarchical multi-agent framework:

  * AGENT 1: Price Movement Agent (Framework: CrewAI | Pattern: ReAct | Weight: 20%)
    - Role: Senior Technical & Price Structure Analyst.
    - Function: Uses MCPStockDataFetcher to evaluate proxy price momentum, RSI(14), 
      MACD histograms, Bollinger Bands, and key support/resistance thresholds in ₹.
    
  * AGENT 2: Macroeconomic Agent (Framework: CrewAI | Pattern: Plan-Execute | Weight: 15%)
    - Role: Chief Macro & Sector Policy Strategist.
    - Function: Analyzes NIFTY 50 baseline regime, India VIX volatility, RBI interest rate 
      trajectory, and sector-specific policy headwinds (e.g., DoT deferred spectrum relief).

  * AGENT 3: Sentiment Agent (Framework: CrewAI | Pattern: ReAct | Weight: 20%)
    - Role: Financial News & Sentiment Intelligence Lead.
    - Function: Uses MCPNewsAnalyzer to parse live RSS feeds from Economic Times, 
      MoneyControl, and Google News, generating VADER compound polarity scores.

  * AGENT 4: Risk Management Agent (Framework: Anthropic ADK | Pattern: Reflection | Weight: 20%)
    - Role: Chief Risk Officer & Downside Stress-Tester.
    - Function: Scrutinizes debt-to-equity ratios, promoter pledges, lock-in expiry schedules, 
      calculating 95% Value-at-Risk (VaR) and Maximum Drawdown thresholds.

  * AGENT 5: IPO Intelligence Agent (Framework: Anthropic ADK | Pattern: Quantitative Audit | Weight: 25%)
    - Role: Capital Allocation & Valuation Auditor.
    - Function: Evaluates QIB vs. HNI vs. Retail subscription ratios, Gray Market Premium 
      (GMP) stability, use of proceeds (fresh issue vs. Offer for Sale), and True Equity Value.

  * AGENT 6: Master Orchestrator (Framework: Hybrid CrewAI + ADK | Weight: 100% Synthesis)
    - Role: Investment Committee Chair & Strategy Synthesizer.
    - Function: Gathers all 5 agent reports via the A2A State Bus, computes weighted 
      committee scores, verifies safety guardrails, and derives the Dynamic Exit Plan.

4.2 Model Context Protocol (MCP) Tool Integration
Agents do not hardcode web scraping. They invoke standardized MCP tools:
  - `MCPStockDataFetcher`: Wraps Yahoo Finance with schema validation (`StockDataRequest`), 
    returning price change, technical indicators, and OHLCV series inside an `MCPToolResponse`.
  - `MCPNewsAnalyzer`: Ingests multi-source RSS feeds, strips HTML via BeautifulSoup4, and 
    extracts relevant headlines with provenance timestamps.
  - Network-Resilient Guard: Tools call `is_network_available(0.3s)`. If internet is offline, 
    tools instantly fall back to proxy domain baselines, preventing timeouts.

4.3 Agent-to-Agent (A2A) Protocol Bus
Cross-framework context sharing is achieved via `a2a_protocol.py`:
  - `AgentState`: A centralized thread-safe container holding task metadata, agent outputs, 
    and error states.
  - Message Types: Agents publish `STATE_UPDATE` messages when an analysis completes. 
    Downstream agents ingest upstream state (e.g., Agent 4 reads Agent 1's calculated RSI).

4.4 Dynamic Exit Strategy Formulation
Unlike traditional systems that output a binary decision, Sarthak Nivesh builds a 
three-tier post-listing profit-booking ladder:
  - Tier 1 (+10% to +15% gain): Sell 30% of position; trail stop-loss to Breakeven (0%).
  - Tier 2 (+20% to +28% gain): Sell 40% of position; lock in institutional profit.
  - Tier 3 (+35% to +45% gain): Ride remaining 30% position with dynamic trailing stop.
  - Immediate Capital Protection Stop-Loss (-5% to -8% below listing price): Hard exit.

4.5 Security Guardrails & Verification
  - Input Guardrail: Sanitizes prompts against SQL injection, HTML tags, and prompt injection attacks.
  - Output Guardrail: Enforces decision enumeration (`INVEST`, `PARTIAL_INVEST`, `HOLD`, `EXIT`).
  - Serialization Guardrail: Sanitizes `NaN` and `Infinity` to `0.0` across all API endpoints.

4.6 Observability & Control Tower
  - Full LangFuse trace and span telemetry logging inputs, outputs, tokens, and duration.
  - Real-time logging through `AgentMonitorCallback` connected to the Agent Control Tower UI.
